## 0. 先明确边界

### 当前 Demo 要做到

- 用户粘贴一段金融销售话术或产品说明。
- 系统识别大致产品类型，并输出结构化分析。
- 报告固定展示：原话、通俗解释、风险点、关键参数、原文证据、待确认问题。
- 模型或某个阶段失败时，明确显示失败或部分完成，不能显示成“没有风险”。
- H5 在 360px 宽度手机上可正常输入、等待和查看结果。
- Python 服务端让 Java 开发能够快速找到 Router、Use Case、规则和外部模型适配器。
- 一条命令启动前端和后端，一条命令运行检查与测试。

### 当前 Demo 不做

- 不做账户、支付、订阅、运营后台、多租户和复杂权限体系。
- 不做微服务、Kubernetes、消息队列集群、灾备、高可用和完整监控平台。
- 不做模型训练、微调、多 Agent 或复杂 harness。
- 不做数字人、视频播报、自动投诉和投资建议。
- 不做大而全的 PDF/OCR 平台；文件上传放到 P1。
- 不以公开上线为目标，但仍保留三条最小底线：服务端 Key 不进浏览器、模型输出安全渲染、失败不能冒充安全。

# 第三部分：目标结构与 Java 友好约定

## 5. 推荐项目结构

```text
crusher/
├── frontend-h5/                     # Vue3 + Vant
│   └── src/
│       ├── pages/                   # 输入、任务状态、报告
│       ├── components/              # 风险、证据、关键参数卡片
│       ├── api/                     # OpenAPI 生成 Client
│       └── stores/                  # 只保存任务状态，不保存敏感原文
├── backend-python/
│   ├── pyproject.toml
│   └── app/
│       ├── main.py                  # FastAPI 启动和路由注册
│       ├── interfaces/http/         # Router、Request、Response、异常映射
│       ├── application/             # Use Case 与流程编排
│       ├── domain/
│       │   ├── models/              # Fact、Evidence、Finding、Report
│       │   ├── rules/               # 否定、数值、产品识别规则
│       │   └── ports/               # LLM、知识库、TaskStore Protocol
│       ├── infrastructure/          # 模型、知识文件、内存任务适配器
│       ├── config/                  # Pydantic Settings
│       └── shared/                  # 错误码、日志、通用类型
├── knowledge/                       # 带来源和版本的 Demo 知识文件
├── contracts/                       # CI 从 FastAPI 导出的 OpenAPI 快照
├── tests/                           # 单元、接口、金标、冒烟测试
├── docs/                            # 架构、请求链路、Python/Java 对照
├── scripts/                         # 本地启动与 OpenAPI 导出（不用 Docker）
├── Makefile
├── legacy/streamlit_app.py          # 旧页面只作对照，不继续开发
└── README.md
```

依赖方向固定为：

```text
HTTP Router -> Application Use Case -> Domain Port <- Infrastructure Adapter
```

- `domain` 不导入 FastAPI、OpenAI SDK、MCP SDK 或页面代码。
- `application` 只做编排，不写 HTML，不直接读取环境变量。
- `infrastructure` 负责第三方模型和本地知识文件。
- MCP 只作为未来可选外部接口，Demo 内部直接调用 `KnowledgeRepository`。
- 不做微服务；前后端分离不等于把服务端拆成多个服务。

## 6. Python 与 Java 的阅读映射

| Python/FastAPI | Java 开发可类比为 |
|---|---|
| FastAPI Router | Spring MVC Controller |
| Pydantic `BaseModel` | Record/DTO + Bean Validation |
| `Protocol` | Java interface |
| Application Use Case 类 | Application Service |
| Infrastructure Adapter | Repository/Gateway 实现类 |
| `Depends` | 构造函数依赖注入入口 |
| exception handler | `@ControllerAdvice` |
| pytest fixture | JUnit fixture |
| Pyright strict | 编译期类型检查的补偿 |

### 强制编码规则

- HTTP、配置和模型返回边界使用 Pydantic；领域值对象可用 `@dataclass(frozen=True)`。
- 所有公开函数必须写参数和返回类型；核心路径禁止裸 `dict`、裸 `list` 和 `Any`。
- 外部能力都定义为 `Protocol`，例如 `LlmGateway`、`KnowledgeRepository`、`TaskStore`。
- 依赖通过构造函数显式传入；禁止全局可变对象、猴子补丁和业务入口修改 `sys.path`。
- FastAPI 的 `Depends` 只出现在 HTTP 层或组合根，Domain/Application 不得导入 FastAPI。
- 使用 Pyright strict、Ruff、pytest 和 coverage；规则放进统一 `pyproject.toml`。
- 不创建假的 `@Service`、`@Repository`、`@RiskCheck` 装饰器来模仿 Java。
- 中文注释解释业务不变量、失败状态和为什么这样处理，不逐行翻译 Python 语法。

### Docstring 模板

```python
class AnalyzeTextUseCase:
    """分析一段金融文本。

    Java 对照：AnalyzeTextService#execute。
    前置条件：文本已通过长度检查，request_id 非空。
    处理边界：这里只编排，不实现规则匹配和模型请求。
    业务不变量：分析失败不得转换成“未发现风险”。
    可能错误：INPUT_TOO_LONG、LLM_TIMEOUT、INVALID_MODEL_OUTPUT。
    """

    def __init__(
        self,
        llm_gateway: LlmGateway,
        knowledge_repository: KnowledgeRepository,
    ) -> None:
        self._llm_gateway = llm_gateway
        self._knowledge_repository = knowledge_repository

    async def execute(self, request: AnalyzeTextRequest) -> StageResult[AnalysisReport]:
        ...
```

### Java 开发配套文档

- `docs/开发地图-代码与请求链路.md`：请求链路 + Java/Python 代码对照 + 本项目会用到的 Python 速记。
- 各目录职责说明统一为该目录下的 `project.md`（根目录上手仍用 `README.md`）。
- `.vscode/launch.json` 或等价 Cursor 调试配置：可直接断点启动 FastAPI 与 pytest。
- `make dev`、`make test`、`make lint` 或跨平台等价脚本；**本 Demo 不用 Docker Compose**。

# 第四部分：P0 详细处理方式

## P0-01 冻结 Demo 范围和回归样本

### 要处理

1. 首版只选择 1～2 类当前表现最稳定的产品，不同时证明所有产品都支持。
2. 固定一个输入接口、一个任务查询接口和一套报告结构示例。
3. 把四组否定句错误、模型超时和非法 JSON 写成黑盒失败测试；输入与期望优先保存为 fixture，后续移动模块时只改适配/import，不改期望。
4. 审核现有 `tests/对照-期望输出样例.json`；原文没有写的内容必须改为 `not_disclosed`，不能把旧输出直接当金标。

### 验收

- `docs/demo-支持范围与样例.md` 明确“支持什么、不支持什么、怎么演示”。
- 团队对同一输入的正确输出没有歧义。
- P0-02 开始后不再临时增加产品类型和页面。

## P0-02 重构结构并完成前后端分离骨架

### 要处理

1. 按第 5 节建立目录；旧 `app.py` 移到 `legacy/streamlit_app.py`。
2. 建立最小 `pyproject.toml`、正式包入口和 pytest/Ruff/Pyright 基础配置，保证移动后的模块可导入、可检查。
3. FastAPI 先提供 `/health`、`POST /api/v1/analyses`、`GET /api/v1/analyses/{task_id}` 的空壳。
4. H5 先提供输入页、处理中页、报告空壳和错误页。
5. 建立组合根，把 Gateway/Repository/TaskStore 显式注入 Use Case。
6. 此阶段只搭骨架，不顺手重写规则和 Prompt。

### 验收

- 前端和后端可以独立启动。
- Swagger 能打开，H5 能调用 mock 接口完成一遍页面跳转。
- `legacy` 仍可作为结果对照，但不再新增业务逻辑。

## P0-03 统一配置、错误和任务状态

### 要处理

1. API Key 和模型地址只从后端配置读取；H5 不显示 Key 输入，也不能传任意 `base_url`。
2. 分开两套状态：`TaskStatus=queued/running/completed/failed` 管任务生命周期；`StageStatus=success/partial/failed/not_applicable` 管各分析阶段。
3. 错误至少区分输入过长、模型超时、限流、返回格式错误、规则失败和知识不可用。
4. Demo 使用单进程 `BackgroundTasks` 或受控 `asyncio.Task` + 内存 `TaskStore`；POST 快速返回 `task_id`，GET 查询阶段。只支持单实例，不引入 Redis/Celery/消息队列。
5. 前端只保存 `task_id` 和阶段，不保存输入正文；后端日志不打印完整原文和模型响应。

### 验收

- 模拟模型超时时，H5 显示“模型调用失败”，绝不显示绿色“未发现风险”。
- 浏览器代码、网络响应和构建产物中没有服务端 API Key。
- 刷新页面后可以凭 `task_id` 恢复 Demo 任务状态；服务重启后任务丢失可接受，但必须提示。

## P0-04 建立强类型输入输出 Schema

### 要处理

1. 使用 Pydantic 定义 `AnalyzeTextRequest`、`StageResult`、`AnalysisReport`、`Evidence` 和 `Finding`。
2. 报告固定包含：产品候选、通俗解释、关键参数、风险发现、证据、缺失信息和待确认问题。
3. 分开 `product_risk_grade` 和 `finding_severity`；H5 固定提示“本 Demo 不进行用户适当性评估”，不创建看似已评估的适当性结果卡。
4. 金额用 `Decimal`，枚举禁止散落字符串；DTO 默认拒绝额外字段。
5. FastAPI/Pydantic 是唯一接口实现源，CI 导出 OpenAPI；H5 类型由 OpenAPI 生成。

### 验收

- 缺字段、非法枚举和不可解析金额会得到明确错误，不会被悄悄修成空值。
- API、Swagger 示例和 H5 使用同一字段名与状态。
- `failed + findings=[]` 在 UI 中仍显示失败，不显示“没有风险”。

## P0-05 修正规则、提示词和产品识别

### 要处理

1. 删除“至少找出 N 个风险”要求；只输出 0～N 个有证据发现。
2. 规则增加否定词、数值条件、上下文窗口、主体和触发条件。
3. 产品识别返回多个候选、证据和置信度；低于阈值返回 `unknown`。
4. 模型只做语义抽取和通俗解释；确定性关键词、否定和数值判断由程序复核。
5. 坏正则在启动或测试阶段直接报错，不在运行时静默跳过。

### 验收

- 第一部分四组最小对立测试全部通过。
- 安全文本允许返回零个发现，不为了版面好看而凑数。
- 插入无关句子不会改变产品分类和风险结论。

## P0-06 重组流水线、事实与证据

### 要处理

1. 建立 `AnalyzeTextUseCase`，固定顺序为：预检 → 分类 → 抽取 → 规则复核 → 证据校验 → 通俗解释 → Report。
2. 事实分为 `document_fact`、`calculated_fact`、`general_reference`、`unknown`。
3. 通用知识只能作为参考，不能自动填充当前材料未披露的字段。
4. 每个 Finding 必须包含原文 quote、字符位置、规则或知识来源、置信度和 `needs_review`。
5. 应用内部直接调用 `KnowledgeRepository`，移除每次请求启动 MCP 子进程的路径；异步调用完整使用 `await`，不嵌套 `asyncio.run`。
6. Mermaid 改为 H5 受控步骤卡；Demo 不让模型生成可执行 Mermaid。

### 验收

- 点击任一发现都能看到对应原文。
- 原文没写“保本”时只能显示“材料未说明”。
- 同一输入重复运行时，程序规则结论一致；模型措辞可变化但不能改变结构化事实。

## P0-07 完成 H5 Demo 主流程

### 页面

1. 输入页：一个文本框、产品类型“自动识别/手动选择”、示例按钮、开始分析。
2. 状态页：显示当前阶段、耗时、失败原因和重试按钮。
3. 报告页：顶部先给一句结论，再按关键参数、风险发现、通俗解释、证据和待确认问题分卡片。
4. 错误页：保留输入并允许重试，不把失败渲染成空报告。

### H5 约束

- 单列布局，360px 宽度无横向滚动，点击区域至少约 44px。
- 不依赖 hover、宽屏双栏、固定高度 iframe 和复杂流程图。
- 适配安全区、软键盘、长文本折叠、复制和微信返回行为。
- 所有依赖构建时本地打包，不运行时加载境外 CDN。
- 用户文本和模型文本作为纯文本渲染；如需富文本，只开放受控标签。

### 验收

- Android 微信、iOS 微信和普通 Chrome/Safari 至少各走通一次。
- 长原文默认折叠，展开后证据仍能定位。
- 模型失败、空结果、慢请求和断网均有明确页面状态。

## 7. 每次只投喂一个任务

不要把整份文档一次性交给 Cursor 自动重写。建议顺序：

1. 先把本 MD 放到项目 `docs/`。

## 9. P0 总体验收

- 项目已完成前后端分离，但仍是一个简单模块化单体。
