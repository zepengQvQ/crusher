# 2. 严格执行顺序

## P2-RC-01｜堵住发布门禁与假证据绕过

### 目的

发布门禁必须做到：证据不合法、事实不存在、文案不受引用内容支持时，不能返回 `PUBLISH`。

### 当前问题位置

- `backend-python/app/domain/llm_explanation_guard.py`
  - 当前只校验 ID 是否位于白名单，不校验文案与引用事实是否一致。
- `backend-python/app/domain/validation/publication_gate.py`
  - 当前只调用 `validate_finding_evidence()`，没有校验 `FinancialFact.evidence_refs`。
- `backend-python/app/application/analysis_harness.py`
  - 将没有证据字段的旧 `KeyParameter` 直接包装成 `param:*` 并加入模型事实白名单。
- `backend-python/app/domain/rules/evidence.py`
  - 无效 Finding 被直接丢弃；如果全部丢弃，最终流程仍可能发布成功。

### 必须修改

1. 新增 `validate_financial_fact_evidence(source_text, financial_facts)`：
   - `CONFIRMED` 事实必须至少有一个证据。
   - `0 <= start < end <= len(source_text)`。
   - `source_text[start:end] == quote`。
   - 任一项失败必须进入 `VerificationResult.issues`，不能被允许数值集合继续使用。
2. 调整发布门禁顺序：
   - Schema → 引用存在性 → Finding 证据 → FinancialFact 证据 → 数值/单位/条件 → 边界 → 发布决策。
3. 无效 Finding 不得“丢弃后变绿”：
   - 记录 `dropped_finding_ids` 或验证问题。
   - 存在规则命中但证据无效，结果至少为 `PUBLISH_PARTIAL`，不得为 `PUBLISH`。
4. 解决“合法 ID 支撑任意文案”：
   - 推荐 Demo 方案：用户可见的已确认白话由程序模板根据事实/风险生成；模型自由文本只作为候选草稿。
   - 模型草稿没有可确定验证的语义支持时，不进入 `plain_language.text`。
   - 不要只继续增加几个禁词正则；禁词无法证明语义受事实支持。
5. 增加一个引用目录 `ReferenceCatalog`（名称可调整）：
   - `id → 类型、字段、状态、标准值、限定词、条件、证据`。
   - 发布门禁只接受目录中存在且已经完成证据验证的 ID。
6. `PUBLISH_PARTIAL` 报告只保留程序已验证内容，不保留被拒绝的模型文案。

### 必须新增测试

- 合法 ID + “国家财政兜底”不得发布。
- 合法 ID + 与引用事实无关的定性结论不得发布。
- 伪造 FinancialFact quote/span 不得发布。
- Finding 被证据校验全部丢弃时不得返回完整发布。
- 验证失败时模型原文不得进入最终 `plain_language.text`。

### 验收

- [ ] F-01、F-02 无法复现。
- [ ] 未验证事实不会扩充允许数值、评级或结论集合。
- [ ] 发布门禁失败稳定返回 `PUBLISH_PARTIAL` 或 `REFUSE`。

## P2-RC-02｜统一金融事实账本、证据与稳定 ID

### 目的

所有标为“原文事实/已确认”的参数必须来自同一份 `FinancialFact` 账本，并带精确原文证据。

### 当前问题位置

- `backend-python/app/domain/rules/fact_extractor.py`：旧 KeyParameter 正则和新账本并行，形成两套事实真相。
- `backend-python/app/domain/rules/financial_fact_extractor.py`：只覆盖部分字段，`new_fact_id()` 使用随机 UUID。
- `backend-python/app/domain/rules/product_fact_builder.py`：使用标准化后的展示值回搜原文，找不到证据仍标 `confirmed`。
- `backend-python/app/application/analyze_dual_sources.py`：先用旧主张逻辑生成结论，最后只是把账本附加到响应。

### 必须修改

1. 补齐当前 Demo 支持字段的事实抽取：
   - 贷款：金额、期限、年化利率、还款方式、罚息、提前还款费用、产品风险等级。
   - 结构性存款：期限、收益率/区间/最高值、观察条件、提前支取、费用、本金保障、产品风险等级。
2. `KeyParameter` 改为由 `FinancialFact` 映射生成；禁止两套正则分别得出两个值。
3. 在 `AnalysisReport` 增加向后兼容的 `financial_facts` 字段，H5 可展示事实证据；保留旧 `key_parameters` 供现有页面使用。
4. 生成稳定 `fact_id`：

```text
fact_id = hash(source_content_hash + product_id + field_key + start + end + normalized_value)
```

   - 同一原文、同一事实重复分析 ID 必须相同。
   - 原文、证据位置或标准值改变后 ID 必须改变。
5. `product_id` 和 `source_id` 分开，不要把双材料的 `source_id` 塞进 `product_id`。
6. 产品对比直接使用事实原始证据：
   - `display` 可以是 `100000`，但证据必须仍指向原文“10万元”。
   - `confirmed` 且证据为空必须由模型校验拒绝，或降为 `uncertain`。
7. 双材料和产品对比的结论必须真正由共享事实账本生成，不允许只在响应尾部附加一份未参与判断的账本。

### 必须新增测试

- “贷款金额10万元”标准值为 `100000`，证据仍精确指向“10万元”。
- 贷款完整样例中，每个 `document_fact` 都能找到对应 FinancialFact 和证据。
- 同一输入连续运行两次，事实 ID、值、条件和证据一致。
- “最高3%”“满足条件后2.8%”“不收取违约金”保留限定词、条件和否定关系。
- 单材料、双材料、产品对比针对相同文本得到同源事实。

### 验收

- [x] F-03、F-08、F-10 无法复现。
- [x] `confirmed` 事实 100% 有精确证据。
- [x] 旧 KeyParameter 只是兼容视图，不再是第二事实源。

## P2-RC-03｜修复完整性检查的答案绕过与 500

### 目的

追问答案只有“格式合法、属于允许选项、并被实际应用”时，才能解除阻塞问题。

### 当前问题位置

- `backend-python/app/domain/rules/completeness_checker.py`
  - 当前使用“question_id 存在且 value 非空”直接过滤问题。
  - `CalculationKind(kind_ans)` 可能抛出未处理异常。
- `backend-python/app/domain/models/completeness.py`
  - `ClarificationAnswer.value` 是任意字符串，没有按问题进行验证。

### 必须修改

1. 建立确定性的追问定义表：`question_id → control、allowed_values、parser、apply`。
2. 按钮/枚举答案必须属于对应 options；未知值返回稳定 422，不能当作已回答。
3. 数值答案使用 `Decimal`/正整数解析，并校验合理边界。
4. 未知 `question_id`、重复 `question_id` 明确拒绝。
5. 文档缺失、格式错误、超大小、超页数属于“必须重新提交实际材料”的阻塞项：
   - 点击“知道了”不能解除阻塞。
6. 捕获计算枚举转换错误，返回业务追问或稳定 4xx，禁止 500。
7. 完整性结果应包含规范化后的有效答案，后续 UseCase 必须使用这些值，不能只改变 `can_continue`。

### 必须新增测试

- `product_type_confirm=banana` 失败。
- 无文件但 `doc_missing=ok` 仍不可继续。
- `principal=abc`、`days=-1`、`day_count_basis=banana` 不可继续。
- 非法 `calc_kind` 不产生 500。
- `compare_ab=swap` 必须真的调换 A/B，而不是只隐藏追问。
- `dual_roles` 必须真的写回材料角色。

### 验收

- [x] F-04～F-07 无法复现。
- [x] `can_continue=true` 表示后续 UseCase 已获得可实际使用的完整参数。

## P2-RC-04｜修复累积纠错与事实一致性

### 目的

多次修订必须累积生效；用户修正不得只改展示参数而留下冲突的旧事实。

### 当前问题位置

- `backend-python/app/application/reanalyze_with_correction.py`：新任务只保存本次修正。
- `backend-python/app/application/analyze_text.py`：只把当前 `task.revision.corrections` 传入 Harness。
- `backend-python/app/domain/rules/apply_fact_corrections.py`：只修改 KeyParameter，找不到键时静默忽略。
- `backend-python/app/domain/models/correction.py`：事实修正只按 `parameter_key`，没有绑定父任务的稳定 `fact_id`。

### 必须修改

1. 区分：
   - `revision.corrections`：本次提交的差异。
   - `effective_corrections`：从祖先任务合并后的当前有效修正快照。
2. 合并规则：按事实键/ID last-write-wins，但必须保留每次修订记录。
3. Harness 使用 `effective_corrections`，不能只使用本次差异。
4. 事实纠错优先绑定稳定 `fact_id`，同时校验该 ID 属于指定父任务。
5. 用户提供但原文无法证明的值生成 `USER_ASSERTED` 事实：
   - 不得伪装为 `DOCUMENT_FACT/CONFIRMED`。
   - 不得覆盖原始事实记录；需要明确 `supersedes_fact_id` 或等效关联。
6. 同步映射 KeyParameter 和 FinancialFact；模型输入中不能同时出现互相冲突的有效值。
7. 原文和产品类型变化后，如果旧事实纠错已不适用，应明确拒绝或要求重新确认，禁止静默忽略。

### 必须新增测试

- 修订 1 改金额、修订 2 改期限，修订 2 中两个修改都有效。
- 原报告和修订 1 保持不变。
- 伪造其他任务的 `fact_id` 被拒绝。
- 用户声明值不会获得伪造的原文 evidence。
- 修改原文后，旧证据下标全部重新计算。
- 产品类型改变导致旧字段失效时返回明确原因。

### 验收

- [x] F-09 无法复现。
- [x] 任一新报告都能追溯完整修订链和当前有效修正。

## P2-RC-06｜让双材料、产品对比、追问共用结果门禁

### 目的

P2 的正确性规则不能只保护单材料分析。

### 必须修改

1. 抽出与单材料 Harness 解耦的 `PublicationService/ResultGate`。
2. 双材料对照：
   - 结论双方证据均可定位。
   - 销售话术与正式材料角色明确。
   - 无法比较时输出 `CLARIFY/PUBLISH_PARTIAL`，不硬判一致或冲突。
3. 产品对比：
   - `confirmed` 两侧值都必须有各自材料证据。
   - 不输出推荐、综合排名和“更适合你”。
   - 不同收益口径标记不可直接比较。
4. 证据追问：
   - 回答必须绑定来源材料和精确证据。
   - 关键词命中不等于答案成立；只能展示原文时明确写“找到相关原文，未形成确定答案”。
5. 计算：
   - 只使用用户已确认或账本中已验证的参数。
   - 公式、输入、舍入规则和结果同时返回。
6. 各报告增加统一 `publication` 字段，保持现有字段向后兼容。

### 必须新增测试

- 双材料、产品对比、追问中的假证据均被拦截。
- 产品对比金额证据保留原文“10万元”。
- 追问只找到关键词但没有完整答案时返回 `insufficient_evidence`。
- 所有对外结果只出现 `PUBLISH/PUBLISH_PARTIAL/CLARIFY/REFUSE`。

### 验收

- [x] 所有业务入口共享事实状态、证据规则和最终结果语义。
- [x] 不再出现“单材料安全、产品对比旁路”的情况。

## P2-RC-07｜MCP 真测试、知识来源与结构收口

### 目的

最后验证 MCP 确实可本地运行，并把影响 Java 开发阅读的结构问题收口。

### MCP 必须修改

2. 增加真实 SDK 集成测试：
   - Server 可启动。
   - Tools 列表恰好为白名单。
   - Resources 可列出和读取。
   - 至少实际调用一次分析、产品对比和校验 Tool。
3. 不要依赖 FastMCP 私有字段 `_tool_manager` 作为唯一验收方式，优先使用 SDK 客户端/会话协议测试。
4. MCP 产品对比必须调用 P2-RC-06 的同一门禁。
5. 避免同步函数内部直接 `asyncio.run()` 与 Host 事件循环冲突；优先注册 async Tool。
6. 继续保持：无任意文件、URL、Shell，日志只写 stderr。

### 知识库必须修改

1. `source_name/source_url/source_note/verified_at` 不能只指回当前 JSON 自身来证明内容正确。
2. 涉及监管规定、金额上限、风险等级、产品定义的知识必须有可核查来源。
