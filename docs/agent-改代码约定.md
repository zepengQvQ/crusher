# Agent 改代码约定（当前有效）

以 `origin/main` 最新提交为审查基线。按用户指定的清单编号执行；未指定时以 [`archive/金融话术粉碎机-P2智能分析正确性实施清单.md`](archive/金融话术粉碎机-P2智能分析正确性实施清单.md) 为历史参考（P2-01～P2-10 已完成）。新改动先对齐 [`demo-支持范围与样例.md`](demo-支持范围与样例.md) 与现有测试。

历史任务单（只查阅、不默认继续执行）：[`archive/`](archive/)

这是 Demo，不引入微服务、生产级中间件、Java 服务端或超出约定范围的功能。不引入 Docker。

固定技术方向：
- 前端：Vue3 + Vant H5
- 服务端：Python + FastAPI
- Python 代码必须让 Java 开发易读：强类型、Pydantic 边界、Protocol、Use Case 类、构造函数注入、中文业务 Docstring
- 不使用仿 Java 的自定义魔法装饰器

执行要求：
1. 先阅读相关现有代码和测试，列出准备修改的文件。
2. 先补能复现问题的失败测试，再修改实现。
3. 保留不属于本任务的现有改动，不做大范围顺手重构。
4. 所有错误显式返回，禁止静默 fallback，禁止把失败变成空风险。
5. 修改 API 时同步更新 Pydantic Schema、OpenAPI、前端类型和示例。
6. 完成后运行相关测试；改 API 后执行 `make export-openapi`。
7. 按约定：完成一项可提交一项并推送 `main`（用户另有要求除外）；禁止提交 `.env`。
8. 最后输出：修改文件、行为变化、测试结果、剩余问题、下一编号建议。

以该编号下的「验收」作为结束条件。
