# 开发地图（给 Java 同学）

启动步骤见根目录 `README.md`。  
本文只回答两件事：**一次分析怎么走完**、**想改功能打开哪个文件**。

## 1. 用户点一次「分析」，背后发生了什么

```text
手机页：粘贴条款，点分析
  → 后端收到「新建分析」请求
  → 立刻返回一个任务编号（task_id），页面开始转圈
  → 后台慢慢做：
       检查输入 → 猜产品类型 → 抽关键数字/条款
       → 用规则再核对一遍 → 检查证据是否真在原文里
       → 写通俗解释
  → 结果暂存在「内存小本本」里（重启后端就没了）
  → 页面反复问「任务好了没」
  → 好了进报告页；失败进错误页
```

补充：

- 默认 `MOCK_MODE=true`：不真的去调大模型（省 Key、可断网演示）；规则核对仍是真的。
- 页面上「模拟模型超时」等按钮：故意让任务失败，用来演示错误页。
- 正式演示路径**不会**去跑旧的 MCP / 画流程图那套。

## 3. Python 在本项目里怎么理解（别背概念）

| 你看到的 | 白话 |
|----------|------|
| `pyproject.toml` + `pip install -e .` | 类似 Maven 的「装这个项目当依赖」 |
| `requirements.lock` | 依赖版本锁死，大家装一样的 |
| `.env` | 本地配置文件（Mock 开关、密钥等） |
| `composition_root.py` | 手工 `new` 对象并传给别人用（构造函数注入），没有奇奇怪怪的注解 |
| `Protocol` | 就是 Java 的 `interface` 那种「约定方法签名」 |
| `async` / 后台任务 | 接口先秒回任务号；真正分析在后台跑。规则核对本身是普通同步代码 |

## 4. 容易懵的词（小抄）

| 词 | 意思 |
|----|------|
| Mock | 假的：假装调了大模型，方便演示 |
| task_id | 这次分析的编号 |
| 金标 / golden | 「标准答案」样例，测试要对着它 |
| 回归 | 改完代码再跑一遍，防老问题又冒出来 |
| OpenAPI | 接口说明书（机器可读） |
| 契约 | 「前后端约好字段不能乱改」 |
| 端口 / ports | 这里不是网络端口，是「接口定义」那个意思 |
| 适配器 / infrastructure | 真正连文件、连大模型的实现代码 |
